# 学员课程信息建模建议

## 结论

建议采用 **“在线关联为主，关键字段快照为辅”** 的方案：

- 业务关系字段（如 `student_id`、`course_id`、`term_id`）使用外键/ID 关联。
- 在订单等历史单据中保留课程名称、价格等必要快照字段，避免后续改名影响历史对账与审计。

## 原因

### 仅存文字的风险

- 同名/错别字导致统计口径混乱。
- 课程改名后历史数据难以统一归并。
- 跨模块联动（班期、排课、销课）复杂度上升。

### 仅存关联的风险

- 历史单据展示会随主数据变更而变化，不利于财务审计与复盘。

## 推荐实践

1. 学员、班期、课消等运营模块：实时关联主数据。
2. 订单、收据等凭证模块：写入快照字段（如 `course_name_snapshot`、`price_snapshot`）。
3. 报表层按场景选择：
   - 经营分析报表优先使用关联主数据。
   - 历史凭证报表优先使用快照字段。

## 迁移建议

1. 保持现有接口兼容，先新增快照字段。
2. 回填历史数据并校验一致性。
3. 前端逐步切换到“关联读取 + 快照展示”。
4. 完成后收敛写入入口，避免新数据继续写纯文字。
