# 顾问接入 → 成交 → 交付：角色任务与页面全链路梳理

> 场景：一个新用户（顾问）接入后，推动学员从线索到成交再到交付。本文按“角色-动作-页面-产物”梳理，并标注缺口。

## 1. 角色与主责

- 顾问：线索接入、跟进、促成签约、成交录单。
- 班主任：排班期、入班、交付编排、寄送协调。
- 教练：教学交付、进度记录、结课反馈。
- 财务：收款核销、开票、对账、退款执行。
- 运营（可选）：资料投放与线索来源管理。
- 老板/部门经理：看板、复盘与经营监控。

---

## 2. 全流程主线（含页面）

## 阶段 A：接入与线索沉淀（顾问主导）

1. 顾问登录系统
- 页面：`login.html`
- 产物：会话 token

2. 顾问录入或导入学员线索
- 页面：`students.html`
- 关键字段：`wechat_name/phone/source/follow_status/owner_consultant`
- 产物：学员记录（线索）

3. （可选）运营活动回流线索
- 页面：`materials.html`、`material_campaigns.html`、`material_claims.html`
- 产物：活动领取记录与来源归因

### 当前缺口
- 线索分配缺“抢单/回收池/超时回收”机制。
- 线索质量缺评分与自动分级规则。

---

## 阶段 B：成交与合同票据（顾问 + 财务）

1. 顾问建订单
- 页面：`orders.html`
- 关键动作：选择学员、课程、付款阶段、销售归属
- 产物：订单记录

2. 顾问/法务补合同
- 页面：`contracts.html`
- 产物：合同编号与签署信息

3. 财务处理收款与核销
- 页面：`receipts.html`
- 产物：收款单、核销状态

4. 财务管理开票资料与发票
- 页面：`invoice_profiles.html`、`invoices.html`
- 产物：开票档案、发票记录

### 当前缺口
- 订单→收款→开票之间缺“自动一致性校验链”（应收、实收、已开票）。
- 收款缺统一幂等键（渠道流水号）防重复入账。
- 缺退款审批与退款后自动反结算（分成/工资）链路。

---

## 阶段 C：排班与交付执行（班主任 + 教练）

1. 班主任创建班期
- 页面：`class_terms.html`
- 产物：班期计划（期次）

2. 班主任安排学员入班
- 页面：`student_terms.html`
- 产物：学员-班期关系

3. 教练记录交付过程
- 页面：`delivery_logs.html`
- 产物：交付日志、阶段进度

4. 班主任执行资料寄送（如需）
- 页面：`shipments.html`
- 产物：寄送记录与物流状态

5. 结课后发证
- 页面：`certificate_templates.html`、`certificate_issues.html`
- 产物：证书模板与发放记录

### 当前缺口
- 班期缺容量上限、排期冲突校验。
- 交付日志与结课标准未打通（完成条件未制度化）。
- 证书发放缺“完成条件门禁”（例如必须完成且通过考核）。

---

## 阶段 D：分成与薪酬结算（财务主导）

1. 配置分成规则与范围
- 页面：`commission_rules.html`、`commission_scopes.html`
- 产物：分成规则体系

2. 生成与调整分成明细
- 页面：`commission_calcs.html`、`commission_adjustments.html`
- 产物：分成计算与调节记录

3. 薪资结算与发放
- 页面：`payroll_periods.html`、`payroll_slips.html`
- 产物：工资期、工资单

4. 支出与经营复盘
- 页面：`finance.html`、`department_stats.html`、`overview.html`
- 产物：成本支出与经营看板

### 当前缺口
- 分成缺规则版本快照，历史口径可追溯性不足。
- 工资发放缺渠道回单核销与失败重试闭环。
- 手工调节缺强制审批流与审计落盘。

---

## 3. 每个角色的“每日动作清单”（可直接执行）

## 顾问
- 打开：`students.html` → 新增/跟进线索。
- 打开：`orders.html` → 成交后建单。
- 打开：`contracts.html` → 补齐合同。

## 班主任
- 打开：`class_terms.html` → 建班期。
- 打开：`student_terms.html` → 学员入班。
- 打开：`shipments.html` → 协调寄送。

## 教练
- 打开：`delivery_logs.html` → 记录交付进度。
- 打开：`student_terms.html`（只读/配合）→ 查看在学名单。

## 财务
- 打开：`receipts.html` → 收款核销。
- 打开：`invoice_profiles.html` + `invoices.html` → 开票管理。
- 打开：`commission_*` + `payroll_*` → 分成薪酬。
- 打开：`finance.html` → 成本记账。

## 经理/老板
- 打开：`overview.html` + `department_stats.html` → 经营监控。

---

## 4. 仍然“缺东西”的核心原因（总结）

1. 目前以“页面可操作 + 接口可用”为主，缺“跨模块自动联动”。
2. 关键环节缺审批与审计，导致“能做但不闭环”。
3. 收款、退款、分成、工资之间缺统一事件链。

---

## 5. 建议优先补齐的 6 个点（从高到低）

1. 订单-收款-开票一致性校验与异常预警。
2. 收款幂等键 + 支付回调防重处理。
3. 退款审批与分成/工资反结算。
4. 班期容量与冲突校验。
5. 证书发放门禁（必须满足结课条件）。
6. 分成版本快照与工资发放回单对账。
